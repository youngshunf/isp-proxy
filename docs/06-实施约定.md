## 3. 后端工程约定

- Go 标准库 `net/http`（1.22+ 路由模式），数据库驱动 `github.com/jackc/pgx/v5`，不引入 ORM 和 Web 框架。日志用 `log/slog`。
- 迁移：`migrations/NNNN_描述.sql`，只前进；由 `internal/control/store` 内嵌并在启动时按序执行，`schema_migrations` 记录版本。
- 金额用整数分，流量用字节（`bigint`），时间用 `timestamptz`（UTC）。对外 JSON 时间为 RFC 3339。
- 接入密码需要给用户反复查看，所以可逆加密存储（AES-256-GCM，密钥来自 `ISP_SECRET_KEY`）；登录密码用 argon2id（`golang.org/x/crypto/argon2`）。
- 每个包的业务规则写在服务层函数里，HTTP 层只做解析、鉴权和映射；所有按用户的查询都带 `user_id` 条件（C-W12）。
- 并发与幂等：订阅行带 `row_version` 乐观锁；每订阅进行中任务用部分唯一索引；账本唯一键 `(source_type, source_id, entitlement_kind)`；写接口接受 `Idempotency-Key` 头，存 `idempotency_keys(scope, key, request_hash, response)`。
- 调度：控制面内的单一调度循环（每 5 秒）处理未付款订单过期、保留期满释放、端口冷却到期、检测、告警；全部写成可重入的“扫描 + 条件更新”。到期停用由 agent 计时器执行，不依赖调度。

## 4. HTTP 接口约定

- 会话：用户 Cookie `isp_session`，管理员 Cookie `isp_admin`，均为 HttpOnly、SameSite=Lax、生产 Secure；会话存库，可撤销。
- CSRF：双提交。登录后下发非 HttpOnly 的 `isp_csrf` Cookie，所有非 GET 请求必须带相同值的 `X-CSRF-Token` 头。
- 错误：HTTP 状态 + `{"code": "...", "message": "面向客户的中文说明", "action": {"label": "...", "href": "..."}?}`。代码与前端 `ApiErrorCode` 一致：`unauthorized` 401、`unverified` 403、`forbidden` 403（管理端权限）、`not_found` 404、`conflict` 409、`precondition` 412、`invalid` 422、`quota_exhausted` 429、`rate_limited` 429（带 `Retry-After`）。
- 越权：访问别人的资源一律返回 404，不区分“不存在”和“无权”。对外 ID 为带前缀的随机串（`sub_`、`ord_`、`req_`…，至少 80 位随机），不使用自增整数。
- 契约：`api/openapi.yaml`（OpenAPI 3.1）是唯一事实源；前端类型用 `openapi-typescript` 生成到 `web/packages/api-client/src/generated/`；Go 侧契约测试校验“已注册路由集合 = OpenAPI 路径集合”。

## 5. 控制面 ↔ agent（`internal/agentproto`）

- 传输：agent 主动连接控制面 `:8443`，HTTPS + 双向证书；节点身份取客户端证书 CN（`node:<id>`）。开发证书由 `isp-control dev-certs` 子命令生成到本地目录，不进 Git。
- 拉取期望状态：`GET /agent/v1/desired?after=<revision>`，长轮询最多 25 秒；返回整份期望状态与全局 `revision`。整份下发、声明式对账，agent 只应用比已知版本高的订阅条目。
- 上报：`POST /agent/v1/report` 每 ≤ 5 秒一次，内容为各订阅累计 `used_total`（不是增量）、各订阅已应用的版本、连接数、节点 `persist_ok`、节点时钟。控制面以 `GREATEST` 合并。
- 节点任务：检测出口、比较候选出口等需要从节点发起的动作，作为期望状态里的 `probes` 列表下发，结果经 `POST /agent/v1/probe-results` 回传；结果带探测 ID，重复回传幂等。
- 期望状态中的订阅条目：订阅 ID、版本、`entitled_total`、`expires_at`、`enabled`、`used_floor`、并发与带宽上限、当前接入（版本、用户名、密码、三个端口）、当前出口（版本、协议、地址、上游凭据）。接入或出口变化即生成新的订阅版本。

### 8.1 数据库（`migrations/0001_init.sql`）

| 项 | 决定 |
| --- | --- |
| 对外 ID | `前缀_` + 20 位小写 Crockford base32（去掉 i l o u，100 位随机）。库内 `isp_new_id(prefix)` 作默认值，Go 侧 `store.NewID(prefix)` 同格式；各表 `CHECK (isp_id_ok(id, …))` 拒绝其他格式（含原型 mock 的短 ID）。前缀：`usr adm ses etk mail pln plv tpk tpv nod res sub acc exb evt ord pay rfd trf led tsk req prb alt slt`（`slt` 为 0005 的共享名额） |
| 人读编号 | 订单 `ORD-YYYYMMDD-NNNN`、申请 `REQ-MMDD-NNNN`，序号来自全局序列、不按日重置，只用于展示与客服沟通，查询一律用 ID 并带用户条件；付款识别码 6 位（待核款订单内唯一） |
| 时长模型 | 时长账本以秒计。订阅存 `entitled_seconds_total`（账本合计）、`seconds_before_period`（之前各段已耗尽的秒数）与当前段起点 `period_started_at`，约束 `expires_at = period_started_at + (entitled − before)` 在提交时检查。有效期内续时长、补时由账本触发器直接顺延；保留期内续费与已释放后的重新履约，由应用在重新就绪时把 `before` 设为续费前合计、`period_started_at` 设为就绪时间 |
| 账本写入 | 入账一律 `INSERT … ON CONFLICT ON CONSTRAINT ledger_entries_source_key DO NOTHING`；触发器是 `AFTER INSERT`，跳过的重复条目不会加权益。订阅合计不能直接写（触发器拒绝），扣成负数整体失败 |
| 规则版本 | 迁移内置首期规则 `R-2026-11-08`（§1 取值，月数选项 1/3/6）。收款说明（收款方、银行、账号、附言说明）属于规则版本，内置版本为空串：上线收费前管理员必须发布带收款说明的新规则版本；收款说明为空时服务端拒绝下单（412）。内置版本是**自始生效的兜底版本**（`0003_seed_rules_baseline.sql` 把它的 `effective_from` 改为 1970-01-01）：当前规则按 `effective_from` 取最新，管理员发布的版本生效时间不早于发布时刻，因此无论何时发布都排在内置版本之后、一直优先；从未发布时内置版本在任何时刻生效。（0001 原把它固定在 2026-11-08T00:00Z，早于该时刻发布的规则会在该时刻被空收款说明的内置版本覆盖） |
| 切换后检测 | 换出口与组合更换在节点应用后经新绑定检测一次（`0004_task_verify_probe.sql` 加 `tasks.verify_probe_id`），通过才判成功。失败码 `exit_check_failed`（候选资源隔离）、`exit_check_timeout`（任务超时内未收到结果）；两者都整体回到原接入与原出口，新端口按“节点已监听过”进入冷却。成功时这次检测即新出口的首次检测，不再另排一次 |
| 库存档位 | 套餐当前版本的 `country_code + city` 下 `available` 资源数：0 为 `out`，≤ 3 为 `low`（阈值为配置项），否则 `plenty`；对客户只给档位 |
| 出口独占 | 以切换前验证得到的 `exit_bindings.verified_ip` 为判据，生效与待生效绑定中唯一；后续检测 IP 变化只更新检测字段，不触发唯一约束，由告警处理 |
| 管理员 | 角色 `admin`（读写）、`viewer`（只读，写操作 403 `forbidden`）；只由 CLI 创建；TOTP 记录最近接受的时间步防重放；恢复码 10 个、一次性、只存哈希 |
| 迁移器 | 每个文件一个事务，事务级咨询锁串行化并发启动；已执行文件的校验和变化、库里有程序不认识的更高版本时拒绝启动 |
| 数据库测试 | `pgtest.New(t)` 每个测试一个新库；测试包写 `func TestMain(m *testing.M) { pgtest.Main(m) }`；CI 设 `ISP_TEST_REQUIRE_DB=1`，找不到 PostgreSQL 时失败而不是跳过 |

### 8.3 控制面 ↔ agent（`internal/agentproto`）

| 项 | 决定 |
| --- | --- |
| 上游协议 | 在 `http`、`socks5` 之外加 `https`（R-03.1 要求可录入 `https://` 上游）；M3 用 GOST `http` 连接器 + `tls` 拨号器实现 |
| 长轮询 | 不带 `after` 立即返回；修订号与 `after` **不同**即返回（正常为更新；从备份恢复导致回退时让 agent 重新对账，agent 仍只接受版本更高的订阅条目）；超时 304 |
| 期望状态语义 | 整份下发；列表中消失的订阅由 agent 撤销接入并断开；`expires_at` 零值表示未起算；`max_conns`、`bandwidth_bps` 为 0 表示不限；`access`/`exit` 为空表示无接入/无出口（失败即拒绝） |
| 上报 | 回执带控制面当前修订号与服务端时间（agent 可据此估算时钟偏差）；每订阅可带 `apply_error`（端口占用、证书不可用等），任务据此失败并回滚；`used_by_protocol` 可选，满足 R-02.4 的按入口拆分 |
| 重试 | 客户端 POST 带 `Idempotency-Key`，`net/http` 在复用连接失效（控制面重启）时自动重放一次；`Watch` 对网络错误与 5xx 指数退避（200 ms～5 s），401/403 直接返回 |
| 探测 | agent 只报告观测到的出口 IP、国家、耗时与错误；“与当前不同、平台内独占、国家符合”的比较由控制面计算并写入 `probes`。探测直接经上游访问回显端点，不经过客户接入，不计量 |
| 节点身份 | 只信任 TLS 已验证证书链中叶子证书的 CN `node:<id>`，`id` 匹配 `^[a-z0-9_]{1,64}$`；未知或停用节点 403 |
| 开发证书 | `GenerateDevCerts(dir, …)` 写 `ca.pem`、`ca-key.pem`、`server.pem`、`server-key.pem`、`node-<id>.pem`、`node-<id>-key.pem`（私钥 0600）；已存在的文件复用，可重复执行以追加节点 |
| 尚未覆盖 | R-06.2 管理端的活动连接明细与按连接断开：v1 只上报连接数。M3 以可选字段或新探测种类追加，不破坏 v1 |

### 8.4 平台层（ctl-platform，2026-11-08）

| 项 | 决定 |
| --- | --- |
| 路由与授权 | 业务包导出 `[]httpx.Route`，由 `internal/control/api` 统一挂载并按 `Route.Auth` 检查：`Public`、`User`、`VerifiedUser`（未验证 403 `unverified`）、`Admin`。用户端除账号与目录外一律 `VerifiedUser`，契约测试强制检查。封禁用户的非 GET 返回 412（退出登录除外）；viewer 的非 GET 返回 403 并记审计 `admin.write_denied`（退出、重新生成恢复码除外） |
| Cookie 作用域 | `isp_session` 只设在 `Path=/api`，`isp_admin` 只设在 `Path=/admin-api`，`isp_csrf` 在 `Path=/`；会话令牌 32 字节随机，库里存 SHA-256。登录成功（含验证邮箱即登录、管理员第一步）换发 `isp_csrf`；管理员完成第二步、用户改密时换发会话令牌 |
| 会话期限 | 用户 30 天；管理员第一步后 10 分钟内完成第二步，完成后 12 小时、无操作 1 小时失效；停用的管理员会话立即失效 |
| 限流（首期取值） | 同一邮箱发信 60 秒 1 封、每小时 5 封（对未注册邮箱同样计数，429 不泄露）；用户登录：同一邮箱失败 10 次/15 分钟、同一 IP 尝试 50 次/15 分钟；注册、找回申请：同一 IP 20 次/小时；提交验证码：同一 IP 50 次/15 分钟；改密当前密码错误 10 次/15 分钟；管理员登录：同一邮箱失败 5 次/15 分钟、同一 IP 30 次/15 分钟，第二步失败 5 次/15 分钟。被限流的请求整体回滚，不计入次数 |
| 不泄露注册 | 注册对新邮箱发验证码、对已注册未验证邮箱重发验证码（不改密码）、对已验证或代建邮箱发“该邮箱已有账号”提醒；三者响应相同。账号不存在时仍做一次等价的 argon2id 计算 |
| 验证码存储 | `email_tokens.code_hash = HMAC(派生自 ISP_SECRET_KEY 的 MAC 子密钥, user_id, purpose, code)`；发件箱 `payload` 用 AES-GCM 加密，投递或最终失败后清空 |
| 发件箱重试 | 第 n 次失败后等待 10 秒 × 2ⁿ⁻¹（下次时间记在 `payload.next`），8 次失败标记 `failed`；没有专门文案的 `notice_*` 模板用通用文案 |
| 恢复码 | 10 个，每个 10 位 Crockford base32（显示为 `xxxxx-xxxxx`，输入不区分大小写与连字符）；只存 HMAC |
| 来源 IP | 只在直连地址属于可信代理（默认回环，可配 `trusted_proxies`）时读 `X-Forwarded-For`，取最右一个不可信地址 |
| ctl-core 接入 | 唯一接入点 `internal/control/api/wiring.go`：业务包路由、`admin.Hooks`（封禁时让订阅生成新期望版本、用户详情的订阅与订单）、`agentproto.Server`、调度循环。审计与发件箱分别经 `kernel.Auditor`、`kernel.Mailer` 适配到 `audit.Record`、`mail.Enqueue` |

## 9. 共享出口与直出代理（D-24、D-25，2026-11-08）

业务规则见 01 R-01、R-11、R-16.7、R-18“直出代理”行；本节是实现约定。改动任何一条都要同时改测试与 04。

### 9.1 共享出口（D-24）

| 项 | 决定 |
| --- | --- |
| 套餐 | `plans.exit_mode`：`exclusive`（默认，已有套餐不变）或 `shared`；订单快照保存，套餐改动不追溯 |
| 资源 | `upstream_resources.max_tenants`（≥ 1）；录入时不填取配置 `core.shared_exit_default_capacity`（默认 3）。上限为 1 的资源只给独享套餐 |
| 名额 | 一个资源的占用 = 待生效与生效的出口绑定 + 未过期的订单预留 + 换出口任务预留 + 冷却中的名额。独享占用独占整份资源；共享占用合计 ≤ `max_tenants`。不变量由数据库约束或在锁住资源行的同一事务内检查保证，并发抢最后一个名额只有一个成功 |
| 同 IP 规则 | 独享订阅的出口 IP 在平台内唯一；共享订阅的出口 IP 不能是任何独享订阅的出口 IP |
| 挑选 | 独享：空闲资源中优先 `max_tenants = 1`，再随机。共享：`max_tenants ≥ 2`、无独享占用、有空位的资源中按当前占用升序，同数随机 |
| 冷却 | 共享订阅换出口或保留期满释放时，腾出的名额冷却 D-18 的天数（7 天）后才再分配；独享沿用现有资源冷却 |
| 隔离 | 共享资源被隔离或停用时，为其上每个订阅产生告警；资源详情列出受影响订阅 |
| 展示 | 前台套餐卡与订阅显示“独享 / 共享”；共享订阅详情显示“最多 N 人共用”（N 为所分配资源的上限），不显示当前人数和其他订阅任何信息 |

实现中细化的决定（2026-11-08，名额模型细节见 04 §7.6）：

| 项 | 决定 |
| --- | --- |
| 出口类型不可改 | 只在新建套餐时选（`PlanCreateInput.exitMode`，缺省 `exclusive`）；之后发布新版本、上下架都不改它。已售订阅按 `subscriptions.exit_mode` 执行，续费与重新履约沿用 |
| 存量数据 | 迁移给已有资源 `max_tenants = 3`（列默认值），已有套餐、订单、订阅、绑定全部是 `exclusive`。存量资源空闲时会被共享订阅选中；只想卖独享的资源由管理员改为 1 |
| 名额表 | 共享的订单预留与冷却名额记在 `resource_slots`（ID 前缀 `slt`），共享订阅的待生效与生效绑定直接计入占用，不另设任务预留；共享资源的库存状态保持 `available`，满员时对外显示为 `bound`。名额到期由调度按业务时钟删除 |
| 改上限与连接 | 绑定上限 1～100；不能低于当前占用，有共享占用时不能改为 1。资源上有共享绑定或订单预留时不能改连接信息；改连接信息时清掉冷却名额（出口已变） |
| 隔离告警 | 每个订阅一条 `upstream_error`（critical）告警，去重键 `shared_exit_down:<资源>:<订阅>`，带 `resourceId` 与 `subscriptionId`；订阅换走或资源重新上架时关闭。资源上有进行中的切换时拒绝人工隔离或停用（409） |
| 候选比较 | `uniqueOnPlatform` 对共享订阅的含义是“候选 IP 不是任何独享订阅的出口 IP”；共享订阅不能比较独享出口或上限为 1 的资源，独享订阅不能比较已有共享占用的资源（都在发起比较时 409） |
| 库存告警 | `stock_low` 按（地区，出口类型）分别计算，共享的去重键带 `:shared` 后缀，档位按剩余名额 |

### 9.2 直出代理（D-25）

| 项 | 决定 |
| --- | --- |
| 数据 | 订阅类型 `subscriptions.kind`：`isp`（默认）或 `direct`；部分唯一索引保证每个用户最多一个未删除的 `direct` 订阅。直出订阅有接入（三个端口与凭据，换接入规则同 ISP 订阅），没有出口绑定、上游资源、订单和流量账本条目 |
| 赠送与收回 | 管理员在用户详情勾选赠送并填带宽上限（Mbps，默认配置 `core.direct_default_bandwidth_mbps` = 10；并发上限取 `core.direct_max_connections` = 64）；取消勾选即收回（删除订阅、撤销凭据、释放端口进入冷却）。都记审计 |
| 有效期 | 不存储到期时间，每次生成期望状态时计算：可用截止 = 该用户所有时长有效（已开始、未到期、未删除）的 ISP 订阅中最晚的到期时间；没有则阻断原因为 `no_paid_subscription`。付费订阅续时长、到期、删除、开通都要让直出订阅生成新期望版本；agent 按截止时间到点停用（≤ 1 秒） |
| 额度 | 不限流量：期望状态显式标记不限额，agent 不做额度耗尽停用；仍计量并上报，前台后台展示累计用量 |
| 数据面 | 期望状态显式标记直出；agent 只对标记为直出的订阅经本机拨号（仍经 egress 策略），未标记直出且没有出口链的订阅照旧拒绝。直出另封 465、587（25 已封） |
| 展示 | 前台“我的 IP”单独一张直出卡：不显示国旗，显示服务器直出标记、带宽上限、累计用量、“跟随付费 IP，至 …”；可复制连接、换接入；不能续购、不能换出口 |

实现时的细化（2026-11-08）：

| 项 | 细化 |
| --- | --- |
| 接口 | `PUT /admin-api/users/{userId}/direct-proxy`（`{bandwidthMbps?, reason?}`，带宽 1～10000，返回订阅详情；幂等：已赠送时只改带宽，开通失败时重新下发）；`DELETE …/direct-proxy?reason=`（幂等，返回 204）。`GET /admin-api/users/{userId}` 增加 `direct`（`subscriptionId`、`lifecycle`、`bandwidthMbps`、默认带宽、并发上限）。订阅视图增加 `kind`、`direct`（`bandwidthMbps`、`maxConnections`、`paidUntil`），直出订阅的 `plan` 为 `null`、`time.expiresAt` 取 `paidUntil`；后台订阅列表可按 `kind` 筛选 |
| 开通 | 新任务类型 `direct_grant`：生命周期 `pending` → `active`（节点应用后）或 `fulfill_failed`（重新赠送即重试）。节点取该用户最近 ISP 订阅所在的在线节点，没有则取第一个在线节点，都没有返回 412 |
| 阻断 | `no_paid_subscription` 排在 `expired` 之后、`traffic_exhausted` 之前；直出订阅不会出现 `traffic_exhausted`。封禁、暂停照常生效 |
| 期望状态 | `expires_at` 取已开始、未删除的 ISP 订阅最晚到期时间（不按当前时间过滤，到点由 agent 停用）；视图里的 `paidUntil` 只算尚未到期的 |
| 拒绝 | 直出订阅不能入账（账本触发器兜底）、不能续购或买流量、不能申请换出口、不能走通用删除（提示到用户详情收回），后台订阅详情隐藏这些操作 |
| 事件 | 复用 `adjusted`（赠送、改带宽）、`ready`、`deleted`；审计动作 `direct.grant`、`direct.update`、`direct.retry`、`direct.revoke` |
| 数据面 | 直出拨号时主机名只解析一次并按结果拨号（IP 固定，见 docs/04 §6.1）；只支持 TCP |
| 未做 | 直出没有出口 IP 检测（现有检测绑定在出口资源上） |
