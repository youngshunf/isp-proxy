## 2. 本轮审阅处理的边界

| 容易遗漏的问题 | 本稿处理 |
| --- | --- |
| 权益绑在连接上，连接泄露只能连同 IP 一起换 | 权益属于订阅；接入、出口各自有版本，可独立或组合更换 |
| 换接入后旧连接仍可用 | 旧凭据、旧端口立即失效，存量连接 ≤ 1 秒关闭；端口冷却后才复用 |
| 组合更换出现“新接入走旧出口”的中间态 | 新接入直接绑定新出口，失败整体回滚 |
| 知道端口的第三方用垃圾流量耗光客户额度 | 认证成功后才计量 |
| 直接采用 GOST `limiter/quota` | 已核对它不满足要求（监听器层计量、写后累加、空闲不断、到期不限制），改在本仓的连接包装上计量 |
| 用处理器认证后的限速接缝计量 | 原型证明普通 HTTP 首个请求正文会绕过它；改为连接包装计量，认证器回填结果 |
| GOST 链缺失或节点不可选时从中转直连 | 出口链包装为失败即拒绝，原型以金丝雀端点验证 |
| 删除 GOST 服务就以为连接断了 | `service.Close()` 不关闭存量连接，需要自建连接表 |
| 三种协议各一份余额 | 同订阅共用一个计量 key |
| 只统计不扣量，或只禁止新连接 | 先授权后转发；耗尽时主动关闭全部连接 |
| 崩溃后重复扣费或发放免费流量 | 累计值单调上报、取最大值；崩溃只少计不多扣 |
| 反复点击确认收款重复加额度 | 账本以业务来源键唯一约束 |
| 充值把暂停或封禁的订阅重新启用 | 可用条件取交集，状态维度互不覆盖 |
| 月度套餐每月清空或再送流量 | 包月时间边界不是发放事件 |
| IP 释放后客户流量无处可用 | 续时长即重新履约；管理员可在同用户订阅间划转 |
| 换出口时换到别人正在用的 IP | 新出口须不同于原出口，且未被其他有效订阅占用 |
| 控制面宕机后过期订阅继续转发 | 到期在数据面按本地计时器执行 |
| 供应商故障静默回落服务器公网 IP | 显式失败，禁止直连 |
| 代理被用于发垃圾邮件或访问内网 | 默认封禁 25 端口、私网与云元数据地址 |
| 未做合规评估就对外销售 | R-13.10 合规门槛 |

这是一轮文档自查，不是独立安全审计，也不是计费实现正确性的证明。
